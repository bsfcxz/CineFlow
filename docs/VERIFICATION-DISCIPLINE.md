## 为什么需要这份文档

`AGENTS.md` §8.1–§8.3 讲的是**"要跑什么"**，本文讲的是
**"跑了也不一定算数"**。

三件事根因相同：**验证手段本身没有被验证**。

每次都很隐蔽 —— 测试是**绿的**、脚本是**通过的**、数字是**写了**的，
但**结论是错的**。危害比"没验证"更大：
**没验证至少知道自己不知道**；这三类会让人**确信自己已经验证过了**。

## ① 断言不得被"注释/文档/相邻代码"满足

### 实测事故

用 `body.contains('s.videoRange')` 断言"接线存在"，
而该字符串**在注释里也有一份**（注释解释"为什么要读它"时写了 `s.videoRange`）。

⇒ 把真代码删掉（只留注释），测试**照样全绿**。

这类假绿尤其危险：它出现在**反向注入"想验证测试是否有效"的时候** ——
注入让你以为"测试确实抓住了"，实际什么都没抓住。

### 规则

1. **读源码做断言前先剥注释**。
   本仓库统一用 `readCode()`：去块注释（`/\*[\s\S]*?\*/`）+ 行注释（`//[^\n]*`）。
   见 `test/player_session_wiring_test.dart` 的实现。

2. **断言要落在"必然会变的那一行"，而不是关键词**。
   - ❌ `manifest.contains('POST_NOTIFICATIONS')`
     —— manifest 的注释里解释这条权限时也写了这个名字
   - ✅ `manifest.contains('uses-permission android:name="android.permission.POST_NOTIFICATIONS"')`
     —— 删掉权限行，断言必红

3. **断言要精确到分支**。
   `contains('k?.pause()')` 在同一方法里可能命中**多处**
   （`pause` / `stop` / `pauseByFocusLoss` 三个 case 都调它）⇒
   只把其中一处改回错误写法，全文断言**仍为真**。
   ⇒ 改为**按 `case` / 方法体切片**再断言。

4. **相邻代码同理：窗口太宽会把下一个方法吃进来**。
   实测：用固定长度 1800 取 `updateState` 的方法体，
   越界吃到了 `clearState` 的 `catch`，导致断言指向了错误的代码。
   ⇒ 用**下一个方法名**作右边界，而不是拍一个长度。

## ② 反向注入必须"注入到真代码"，且注入脚本自身要复核

新增测试 / 守卫脚本后，**必须制造它应该抓住的缺陷，确认变红**（`AGENTS.md` §8.1 要求）。
但**注入本身也会假绿** —— 实测踩了两次：

| 你以为 | 真相 |
|---|---|
| "注入无效，测试没抓到" | **`replace(..., 1)` 只改到注释那处**，真代码根本没动 |
| "测试抓不到这条" | 该关键字在文件里**出现多处**，只改一处其余仍满足断言 |

**两次都差点让我去"修测试"，而测试其实是对的。**

### 规则

1. **注入前先 `print(命中次数)`**；命中 >1 处时**明确写"改几处"**，别默认 1。
2. **注入后必须确认 `analyze` 仍为 0 error** ——
   否则"变红"可能是**编译错**，不是断言抓到的。
   本仓库已因此误判过 2 次（把编译失败当成"测试有效"）。
3. **注入脚本要还原并断言还原一致**：
   ```python
   finally:
       for p, orig in files.items():
           write(p, orig)
       assert all(read(p) == orig for p, orig in files.items())
   ```
   否则会把注入残留**提交上去**。
4. **注入项要覆盖"真实缺陷形态"**，不只是"删一行"。
   例：本轮注入 `if (false) {   // 注入：永不申请` 比
   `删掉整个焦点申请` 更接近真实错误（条件写错）。

## ③ 数字必须来自**实际输出**，不得推算

### 实测事故

台账写"`flutter test` **859 例** / 新增 **19**"，
实际是 **847 例 / 新增 7** ——

我按"两个新测试文件共 19 例"**推算**，而且**没跑就填了**。

`AGENTS.md` §8.1 已经记着"**286 / 377 / 408 都当过当前值**"，
**这是重犯**。

### 规则

1. **测试数、耗时、体积、行号，一律粘贴命令的实际输出**。
2. **禁止**"这次加了 N 个测试所以总数是 M+N"这类心算 ——
   合并 / 删除 / 参数化会让它对不上。
3. 写"通过 N 项"时，**N 要能在输出里逐条指出来**。
4. 台账里的数字若引用自其它轮次，**标注它来自哪一轮**，别当成现值。

## 一句话判据

> 在说"已验证"之前，先问自己：
>
> **这个验证结果，有没有可能在我删掉真代码之后依然成立？**
>
> 若答案是"有可能" —— 那就不是验证，只是**看起来像验证**。
