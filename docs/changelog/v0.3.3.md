### 🔄 「我的收藏」= 「我的追剧」，真正的幂等双向同步

| 方向 | 之前 | 现在 |
|---|---|---|
| 点「追剧」→ 服务端收藏 | ✅ | ✅ |
| 服务端收藏 → 追剧 Tab | 只读本地表 ⇒ **不出现** | ✅ 自动同步 |
| 服务端取消收藏 → 移除本地 | ❌ 没做 | ✅ 做（带安全阀门）|

**安全阀门（重要）**：本地可能有"**库里还没有**"的外部订阅（先订阅、等入库）——
它们**在服务端没有对应收藏**。若按"服务端没有就删"，会把这些**全删掉**。
⇒ 新增 `syncedToServer` 列区分两种"服务端没有"：
| 服务端 | 该列 | 动作 |
|---|---|---|
| 有 | 任意 | 写入 + 标记 ✅ |
| 没有 | **true** | 用户在服务端取消了 ⇒ **删本地** |
| 没有 | false | 外部订阅 ⇒ **保留** |

### 🐛 修掉的 9 个真实 bug

| # | 现象 | 根因 |
|---|---|---|
| 1 | **在媒体库里的剧却显示"不在媒体库"** | 映射表用 `Limit: 5000`，而服务器有 **5711** 部剧集 ⇒ **静默截断 711 部** |
| 2 | 同上（第二个原因）| `ids` 与 `apis` **下标错位**（某台没有该剧时不 push ⇒ 长度不等）|
| 3 | 卡片不显示"已看 X/Y" | 进度链用 `limit:1000` ⇒ 同样截断 ⇒ 改用**逐部精确**的未看数（0 额外请求）|
| 4 | **订阅"忽有忽无"** | 同步误用 `toggle`（**翻转**语义）⇒ **每次同步都把上次写入的取消掉** |
| 5 | 服务器一挂就删光订阅 | "查询失败"被当成"用户已取消" ⇒ 加 fail-safe：**任一服务器失败即跳过删除** |
| 6 | 已完结的剧显示"连载中" | 列表请求的 `Fields` **缺 `Status`** |
| 7 | 卡片显示英文 `Continuing` | 状态回退路径没做规范化 |
| 8 | 「已完结」计数恒为 0 | 4 处用**中文字面量**去比 Emby 的**英文值** |
| 9 | 详情页「下次更新」不显示 | `best == null` 的早退**挡死了本地时刻表**（0 网络的源）|

### ✍️ 文案口径修正：不再替用户"下结论"

`未看数 == 0` 时原显示 **`已追完`** —— 但那是**对用户行为的断言**。
数据只能证明"库里的集都被标记为已看"（可能是入库时批量标记的），
**无法区分"你真的看完了"和"库里的集被标成已看"**。

⇒ 改为 **`无未看集`**（只陈述数据事实）。

> 同一原则：不把"加载失败"伪装成"暂无内容"。

---

### 🎬 数据聚合（按用户要求）

> "单台也能显示（有就显示），多台的时候自动聚合。"

- **单台有** ⇒ 直接显示（不再要求两台都成功）
- **多台都有** ⇒ 集数取**最全**的那台；进度选**看得最远**的那台
- ⚠️ 分母与分子**必须同源**（`已看 X/Y` 的 X 与 Y 来自同一台）——
  否则会造出"已看 12/193"这种来自两台的假数据

---

### ⚠️ 已知限制

- **debug 签名**（与历史版本一致，非正式发布签名）
- **仅 arm64-v8a**（本项目只发单一 ABI，体积更小）
- **一台服务器可能不可达**：若 Emby 服务器本身离线，追剧页会显示本地/IPv6 可用那台的数据；
  fail-safe 保证**不会**因此删除订阅
- **腾讯视频**仍拿不到周更时刻（穷尽验证过 4 种入口，页面 HTML 不含该数据）⇒
  腾讯的剧沿用平台惯例 20:00
