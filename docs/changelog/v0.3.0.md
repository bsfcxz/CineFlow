## v0.3.0：播放内核换成安卓原生 mpv，启动不再闪白屏

这个版本做了一件大事：**把播放内核从 media_kit 插件换成了自持的安卓原生 mpv**
（libmpv + Kotlin/JNI 薄桥 + Flutter 纹理输出）。

换内核的动机不是「追新」，而是原来那套够不到我们需要的东西：
`vo` / `gpu-context` / `hwdec` / `demuxer-*` 这些**启动期选项**只能经插件 API 间接设置，
插件没暴露的就够不到；而且插件自带各平台预编译库，升级节奏不由我们决定。

顺带修掉了「打开应用白屏」——这个问题有**两个独立原因**，都挺隐蔽。

### 本版亮点

#### 播放内核：安卓原生 mpv

内核换成自持的 `libmpv.so`（单文件自包含，ffmpeg 已静态链入）+ Kotlin/JNI 薄桥。

**渲染走 Flutter 纹理，不是 PlatformView。** 这不是随便挑的：
纹理是普通 Flutter 图层，弹幕、手势、控制层直接叠上去就行，
**不需要任何手势仲裁**——而 PlatformView 走混合合成，手势冲突正是最难缠的那类 bug。

真机实测（Android 13 / arm64）：

```
[mpv/vd] Using hardware decoding (mediacodec).
AO: [audiotrack] 44100Hz stereo 2ch float
VO: [gpu] 1920x1080 mediacodec
```

硬解生效、音画都出来了，`h264 1080p60 + aac` 播放正常。

顺带加了一个**真机集成测试**（`integration_test/player_kernel_test.dart`），
它会真的建纹理、起播、seek、改倍速、暂停再销毁。
这是**唯一**能验证「Dart → 通道 → Kotlin → JNI → libmpv」整条链路的测试——
普通单测跑在桌面 VM 上，碰不到原生层，链路断了也照样全绿。

> 🔧 **需要你动手（仅开发环境）**：`media_kit` 三件套依赖已移除。
> 如果你本地还留着旧的构建缓存，建议 `flutter clean` 一次。

#### 白屏修好了（两个原因）

**原因一：APK 入口被集成测试污染。** 跑 `flutter test integration_test/...` 会
**用测试文件当入口**重新构建 APK。之后装上去启动的是测试框架，不是应用本身——
Dart 虚拟机正常起来（所以不像崩溃、进程也在），但 `main()` 一行都没执行，屏幕全白。

诊断特征很好记：**正常启动的日志里必定有 `[GoCore] 已加载` 和 `[DB] 就绪` 两行**，
缺了就是入口不对。

**原因二：启动背景是模板白底。** `launch_background.xml` 一直是 Flutter 模板原样
（`@android:color/white`，连 `"Modify this file to customize your launch splash screen"`
注释都还在）。冷启动实测**纯白占 94.6%**，与随后的深色界面强烈割裂。

现在改成品牌深蓝底 + 居中标记，实测纯白降到 **0.0%**。

#### 新增「关于」页

「我的」页新增入口（底部版本号也可点）。里面写了应用介绍、技术栈、
**开源致谢（带各项目的 GitHub 地址与许可）**，以及免责声明。

免责声明是合规必需：明示本项目是**第三方客户端，与 Emby Corp.、115 网盘、豆瓣均无关联**，
不托管任何影视内容。这些以前只躺在仓库的 `NOTICE` 文件里，用户看不到。

#### 服务端数据面打通：不再自己重算服务端已有的东西

这一块是**被用户点出来的**：*"这些东西本来你应该能够从 emby 服务端全部拿到。"*
核实后确实成立 —— 此前多处是"客户端自己算服务端早就有的东西"，且算得更差：

| 原先（客户端自己算） | 改为（服务端直接给） | 差别 |
|---|---|---|
| 拉全季分集、遍历进度、推断"看到第几集"（91 行） | `GET /Shows/NextUp` | 2 次请求 → **1 次**，且服务端有完整观看历史 |
| 靠猜章节名含"片头"/"intro"来跳片头 | `ChapterInfo.MarkerType` | 消除漏检（"主题曲"/"OP"）与**误检**（"片头曲欣赏"会跳过正片） |
| 单独发一次请求取章节 | 章节随 `PlaybackInfo` 一起返回 | 省一次往返 |
| 自己拼音轨/字幕显示名 | `MediaStream.DisplayTitle` | 服务端给 `Chinese Simplified (PGSSUB)`、`Mandarin EAC3 5.1 (默认)` |

字段对照依据是**官方 swagger**（服务端生成的 OpenAPI 4.10.1.0）+ **真机 curl 实测**。
`MediaStream` 的解析字段从 9 个补到 25 个（官方共 56 个）。

**顺带修掉一个会导致"切错轨"的错误**：Emby 的流索引是 ffmpeg **全局**索引，
而播放内核的 `aid`/`sid` 是**每种类型各自从 1 开始**编号 —— 两者**不是一回事**。
实测某片里音轨的数字碰巧相同（掩盖差异），但**字幕一个 Index=4、内核却是 1**，
按 id 匹配会导致**字幕永远切不上**。已改为按 mpv 的 `ff-index` 对齐。

#### 播放器交互：按你的反馈逐条改

- **剧集详情页按钮**改回「立即播放 / 继续播放 第 N 集」（不再显示"选集"），
  并且**真正下钻到分集起播**；已看完则重播最后一集。
- **快进/快退**：原来那两个键其实是"上一集/下一集"，而且从首页进入时**处于禁用状态**
  （按了没反应）→ 改为 **±10 秒**，任何进入路径都可用。
- **长按屏幕倍速播放**：原来硬编码 2.5x，且有个 bug（常速若正好是 2.5x，松手会被错误重置为 1.0x）
  → 改为可选档位（1.5/2/2.5/3，默认 2x）。
- **「跳片头」与「长按倍速」移入「我的 → 播放设置」**，不再占播放中的控制条。
- **控制条按钮按"有没有别的选择"显隐**：电影只有一部就不显示「选集」；
  只有一条音轨就不显示「音轨」；没有字幕轨就不显示「字幕」。
- **播放器启动不再闪红**：原来加载失败的提示是整圈红边框，深色画面上很刺眼。

#### 弹幕：对照 B 站补齐

新增**弹幕类型开关**（滚动 / 顶部 / 底部）· **弹幕速度** · **弹幕加粗** · **防挡字幕**。
并修掉两个"设了没反应"的问题：速度没接进渲染、加粗对已缓存的弹幕无效。

#### 界面设计系统重建

- **对比度修复**：`text3`（99 处小字）原本只有 3.76:1，低于 4.5:1 标准 → 提到 **5.40:1**。
- **排版收敛**：235 处字号散成 **22 个值**（含大量 0.5px 级差）→ 收敛为 **9 档**。
- **图标尺寸收敛**：15 个值 → **4 档**；新增统一的图标徽章组件。
- **补齐 15 项主题配置**，并修掉 **8 处"切换主题色不变"** 的硬编码颜色。
- **响应式**：首页轮播与海报网格不再写死尺寸（原来在别的屏幕尺寸上会挤或拉伸）。
- **修 5 处"点不中"的按钮**：最小的一处可点区域只有 **16×16**（48dp 标准的 1/9）。

### 其他改进

- **启动图标审查**：桌面图标本来就是品牌图标（深紫黑底 + 蓝紫折带，五档密度齐全），
  但**启动页是模板白底**——已修（见上）。
- **新增 AI 协作规范**：`docs/AI-MEMORY.md`（开发记忆库，含进度快照与变更台账）
  与 `docs/AI-DISTRIBUTION.md`（分发规范）。
- **`check-dev.ps1` 开发门禁**：一条命令跑完静态分析 / 单测 / 门禁 / 产物校验 / 真机冒烟。
- **修复 `release.yml`**：它的 YAML **语法是错的**，GitHub Actions 根本无法解析——
  也就是说这个自动发布工作流**从来没有成功运行过**。已修复并补上两处缺失的版本校验。
- **build number 现在会自动递增**：以前 `versionCode` 恒为 `1`，
  导致新包比设备上的旧包「版本号小」，`adb install -r` 会报 `INSTALL_FAILED_VERSION_DOWNGRADE`。

### 修好了

- 打开应用白屏（两个独立原因，见上）。
- 启动瞬间的整屏白闪，以及冷启动时**图标尺寸跳变**。
- **启动图标与应用内图标不是同一个**：应用内原本是"自绘的方块+C"，
  和桌面图标长得像但不是一张图 → 现在三处（桌面 / 启动屏 / 应用内）**同源**。
- 「播放历史」页**早已做好却没入口**：首页「继续观看 → 全部」以前弹「即将推出」→ 现在能进去了。
- **首页内容只占上半屏**（大片空白）：原因是可播类型判断在客户端与服务端口径不一致，
  剧集被过滤掉了 → 修复后首页内容占屏从 **42% 提到 72%**。
- 失败被伪装成"即将推出"（收藏/标记失败时）→ 现在给出真实原因。
- 播放失败时真实错误被吞掉、日志里什么都没有 → 现在保留完整原因。
- 文本字幕不显示（播放内核缺字体路径 `sub-fonts-dir`）。
- `release.yml` 的 YAML 语法错误（工作流此前完全不可用）。
- `versionCode` 不递增导致无法覆盖安装。

### 升级须知

- ⚠️ **APK 使用 debug 签名**（已知限制，见 AGENTS.md §7.16）：仅供自用与体验，
  **不要用于正式分发**，也无法上架应用商店。安装时系统提示「未知来源」属预期。
- 仅提供 **arm64-v8a** 单架构包，32 位设备与部分模拟器装不上。
- **本版换了播放内核**，且改了剧集起播路径（改为服务端 `NextUp` 决定播哪一集），
  建议首次使用后走一遍：起播 / seek / 倍速 / 音轨切换 / 字幕切换 / 选集 / 自动连播。
  如果遇到以前能播、现在播不了的片源，请提 issue 并附片源编码信息——
  这是换内核最需要盯的回归面。
- **音轨/字幕的默认选择可能与你习惯不同**：现在会**按服务端指定的默认轨**起播
  （这是对的，但如果你以前习惯手动切，会感觉"它自己选了"）。
- 已知限制（未修）：**无通知栏控制 / 蓝牙耳机键 / 后台播放**（Media3 会话层尚未实现）、
  无 401 自愈（token 失效需重新登录）、播放中可能熄屏（无 WakeLock）、
  115 网盘走非公开接口存在风控风险。
- 无数据库迁移、无破坏性变更。

完整改动见 [v0.2.0 → v0.3.0](https://github.com/bsfcxz/CineFlow/compare/v0.2.0...v0.3.0)。
