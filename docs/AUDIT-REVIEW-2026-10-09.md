## ❌ 不成立的 4 项（逐条给证据）

### ① P2「`vd-queue` 未启用」—— **描述错误：该选项在本构建里不存在**

```
选项名                     在 libmpv.so 里？
vd-queue-enable          **不存在**
vd-queue-max-bytes       **不存在**
vd-queue-max-samples     **不存在**
vd-queue-max-secs        **不存在**
```

**根因**：本构建是
`-Dlibplacebo=disabled -Dvulkan=disabled`（二进制指纹确认），
**vd-queue（解码器帧队列）根本没被编译进来**。

**⇒ 这不是"未启用"（配置问题），而是"没有该能力"（需要重建 libmpv）。**
两者处置完全不同：前者改一行选项，后者要重走 CI 构建。

> ⚠️ 若照"未启用"去加 `vd-queue-enable=yes`，会得到一个**静默 no-op**
> —— 与 `vo=gpu-next` 同类（本仓库已记录这个坑）。

### ② P2「`cache-pause-wait` 与 `cache-secs` 不一致」—— **不存在这个不一致**

```
cache              = yes
cache-secs         = 30        ← 我们设了
cache-pause        = 未设（mpv 默认）
cache-pause-wait   = 未设（mpv 默认）
```

**两者都未设** ⇒ 不存在"配得不一致"。

且它们的**语义本就不同**，不需要一致：
· `cache-secs=30` = 最多缓存 30 秒（**上限**）
· `cache-pause-wait=3` = 起播前至少等 3 秒缓冲（**下限行为**）

**⇒ 但有一条真问题被这个错误描述掩盖了**：
`cache-pause-wait` 默认 3 秒 = **起播前固定等 3 秒** —— 这与
"起播慢"直接相关，**是值得 A/B 的优化点**（已在 `DUAL-KERNEL-OPTIMIZATION.md` 列为 P0）。

### ③ P1「退出播放页后屏幕方向不复位」—— **实测已复位，台账记录过时**

**⚠️ 这条最需要注意**：它对应 `AGENTS.md` §7.21，
而 §7.21 写着"**已试 4 种方案全部失败**"。

**真机实测（本次）**：
```
进播放页 → 点两次全屏 → 窗口 2400x1080（真横屏）
       ↓ 按返回键
返回后立即  1080x2400（竖屏）✅
再等 3 秒   1080x2400（竖屏）✅
```

**⇒ 方向复位已经生效。**

**为什么 §7.21 过时了**：第 53 轮我在 `player_flow_page.dart` 的
`dispose()` 里加了复位（注释原文："`dispose()` 是**所有退出路径的必经点**，
旧页正是在这里做的 —— **新页没对齐**"）。
那正是 §7.21 建议的"让退出路径统一"，只是当时文档没同步。

**⇒ 该更新 AGENTS §7.21**（否则后续代理会去"再试第 5 种方案"，白费功夫）。

**⚠️ 一条方法论教训（我自己先犯了）**：
我第一次测这条时，**播放页也是竖屏**（没进全屏），
于是"返回后竖屏"**什么都证明不了** —— 典型"测了个不会变的东西"。
**第二次**我点了全屏按钮，但**没确认它真的横屏**就继续，结果同样无效。
**第三次**才做对：**先断言 `2400x1080` 确认横屏，再返回**。

### ④ P3「纹理内存泄漏防护」—— **不成立**

**dispose 顺序是正确的**（`NativeKernel.dispose`）：
```dart
await _eventSub?.cancel();          // ① 先停事件，避免回调打到已销毁对象
await _method.invokeMethod('dispose');  // ② 让原生销毁（含 detachSurface）
_textureId = null;                  // ③ 再清 Dart 侧引用
await _stateController.close();     // ④ 最后关流
```

**原生侧确实 detach**（`PlayerChannel.kt` 有 3 处 `MPVLib.detachSurface()`，
含 `onSurfaceCleanup`）。

宿主页 `_textureId` 从未置 null —— 但那是 `int?` **值引用**，
且页面 `dispose` 后整个 `State` 被回收，**不构成泄漏**。

## ⚠️ 需限定条件的 1 项

### ⑧ P2「`interpolation` 在 4K 上 GPU 开销大」—— **仅 4K HDR/DV 成立**

**关键是内核选择规则的顺序**（代码实测，括号配平提取）：
```
[1] t.isHdr                      ← 先判 HDR
[2] isMpvOnlyContainer(...)
[3] t.isHlsStream
[4] h != null && h >= 2000       ← 后判分辨率
[5] t.hasExternalSubtitle
```

⇒ **4K HDR/DV 走 mpv**（`interpolation=yes` **生效**，GPU 开销确实大）
⇒ **4K SDR 走 Media3**（`interpolation` **根本不作用**）

**⇒ 审计这条只在"4K HDR 片源"场景成立**，不是普遍问题。
而 4K HDR 恰恰是"画面优先"的场景（规则 1 的设计意图就是"宁可软解也要画面正确"）
—— 关掉 `interpolation` 会牺牲流畅度换来的画面稳定性。**需实测权衡**。

## 🔴 审计**未提及**、我实测发现的真缺陷

### 点「全屏」**第一次是「退出全屏」**（顺序反了）

**真机实测日志**（连点两次）：
```
第 1 次点全屏 → requestedOrientation = 1  （竖屏）  窗口仍 1080x2400
第 2 次点全屏 → requestedOrientation = 11 （横屏）  窗口变 2400x1080
```

**根因**（`player_flow_page.dart`）：
```dart
bool _immersive = true;              // L493 初值 true

// L623：_boot 里已经设为真全屏态
SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky);

// L2038：点全屏
_immersive = !_immersive;            // true → false ⇒ 走 else
if (_immersive) {
  ... 锁横屏                    // ← 第 2 次才走到这里
} else {
  SystemChrome.setPreferredOrientations([portraitUp]);   // ← 第 1 次走这里
}
```

**⇒ `_boot` 已把系统设成 immersiveSticky（真全屏），
但 `_immersive` 初值也是 `true` ⇒ 状态与实际不一致 ⇒ 第一次点变成"退出全屏"。**

**影响**：
· 用户点"全屏"想要横屏，**第一次却退回竖屏**（看起来像按钮坏了）
· 而这**同时解释了 §7.21 的谜团**：必须点两次才真正进横屏，
  用户往往只点一次就以为"全屏没用"

**⚠️ 讽刺的是**：这段代码的注释里**已经描述过完全相同的 bug**：
> "`_boot` 初始即 `immersiveSticky`，第一次点会**退出**沉浸式（露出系统栏），
> 与'进入全屏'相反"

⇒ 注释识别出了问题，但**修复只改了 `else` 分支的内容，没改初值** ——
所以症状从"看不出变化"变成了"退回竖屏"。

**建议修法**：把初值改为 `false`（因为 `_boot` 已经进过全屏态），
或让 `_boot` 不预设 immersive 而由 `_immersive` 统一驱动（单一事实源）。

## 🔵 合理但暂不做的 2 项

### ⑨ P3「播放器池化（单内核内部）」
**方向合理**，但**无实测数据支撑**：
本仓库有 `[Startup]` 埋点，但**没有测过"连续播放多集时内核创建/销毁的开销"**。
⇒ 建议**先测量**（连播 5 集的 `kernelCreate` 累计耗时），再决定是否池化。
盲目池化会引入"状态残留"风险（上集的轨道选择、音量、滤镜会带到下一集）。

### ⑩ P3「编译期开关的运行时替代」
**方向合理**（远程配置能免重新发版），但：
· 本仓库**只有 1 个**编译期开关（`CF_NEW_PLAYER`）
· 且 P0 事故的**根因已用"翻转默认值"消除**（默认路径即正确路径）
· 引入远程配置 = 引入**网络依赖 + 失败态**（配置拉不到时用哪个？）

⇒ **成本大于收益**。更彻底的解法是**删掉旧页与开关**（单一播放页，问题自然消失）。
