## ADR 写作模板

```markdown
# ADR NNNN：标题

- 状态：提议 / 已接受 / 被取代（+ 日期）
- 决策者：Captain + Architect
- 影响范围：受影响的层（Flutter / data / docs）

## 背景与问题
要解决的问题是什么，约束有哪些。**不要写"我们需要一个好架构"这种话。**

## 决策
一段结论 + 关键实现约定（能指到文件/目录）。

## 替代方案（及未选原因）
表格：方案 / 为什么没选。

## 影响范围
- 哪些文件/目录要同步改
- 会不会破坏 MediaProvider 抽象层

## 回退条件
什么情况下推翻本决策，推翻时要更新哪些文档（ADR 索引、architecture.md、task-board.md）。

## 参考
参考的开源项目与判断依据（仓库 + 借鉴点）。

## 变更日志
| 版本 | 日期 | 变更 |
```

**纪律**：ADR 写的是"当时为什么这么选"，不是事后补的荣誉证书；被取代的旧 ADR 不删，标"被 NNNN 取代"。
