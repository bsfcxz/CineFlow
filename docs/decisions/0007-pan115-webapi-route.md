# ADR 0007：115 网盘接入走 webapi（cookie）路线

- 状态：**已接受**（含明确风险声明）
- 日期：2026-10-05
- 相关：ADR 0002（纯 Dart MVP，曾取消 115）、ADR 0004（Go 核心层）
- 任务卡：CF-P8-115-030 起

---

## 背景

阶段八原定"115 网盘扩展"。ADR 0002 曾把 115 整体取消（仅保留 `MediaProvider` 抽象），
理由是"纯 Dart MVP 不做网盘"。2026-10-05 用户明确要求接入，并给出两个参考仓库，
随后指示 **"使用 115driver 路线试试，如果不行的话放弃 115"**。

调研（详见 `_115_research/`，未入库）确认 **115 有两套互不相通的接口体系**：

| | 官方开放平台 | 逆向 webapi |
|---|---|---|
| 域名 | `proapi.115.com/open/*` | `webapi.115.com` / `aps.115.com` / `passportapi.115.com` |
| 认证 | OAuth 设备码 + PKCE + AppId | **Cookie（UID/CID/SEID/KID）** |
| 门槛 | 需申请开发者资质（个人可申请，审核约 2×7 工作日） | 扫码即用，无需资质 |
| 性质 | 官方支持、稳定 | **非官方**，官方《开发须知》明文禁止调用非公开接口 |
| 风险 | 无 | **风控/封号风险，可能违反 115 服务条款** |

同类聚合播放器或为 GPL-3.0、或无源码发布，均不可作为代码参考；
其中走官方开放平台路线的实现还存在把 AppId/AppSecret 编译进客户端分发的问题
——正是我们弹幕模块遵守的规则所禁止的。

用户随后明确选择 **115driver 路线（webapi）**。

---

## 决策

**走 webapi（cookie）路线**，实现放在 **Go 核心层**（`go/internal/pan115/`）。

### 为什么放 Go 侧（不是 Dart）

1. **UA 绑定必须两处一致**：115 的 CDN 直链与"取地址时所用的 UA"**强绑定**
   （上游 issue `SheltonZhu/115driver#80` 原文"CDN 链接与默认 UA 强绑定"）。
   取地址在 Go 侧发 HTTP，播放要经 media_kit → mpv 设置 `http-header-fields`。
   两处都必须用同一个 UA 常量；放 Go 侧能让"取地址"与"要给播放器的头"同源产出，
   Dart 侧只做透传，漏传风险最小。
2. **加密算法体量大**：取直链接口要求请求体 m115 加密（AES+RSA+XOR 组合）、
   响应体解密。这是纯计算逻辑，本就属于"Go 核心层"的职责（ADR 0004）。
3. **限流需要进程内状态**：直链缓存、取址退避、刷新锁都要求跨调用共享状态。
   Go 侧一个 `Client` 实例天然满足；Dart 侧要靠 provider 手工维持，更易出错。

### 端点的选择（实测驱动，不是照抄）

| 能力 | 用哪个 | 为什么 |
|---|---|---|
| 扫码 token / 状态 / 登录 | `qrcodeapi.115.com` + `passportapi.115.com` | 实测均 **200 可用**；且无需凭据即可拿二维码 |
| 二维码图片 | `qrcodeapi.115.com/api/1.0/mac/1.0/qrcode?uid=` | 实测返回 **image/png**（554B，PNG 魔数）→ **无需引入二维码库** |
| 文件列表 | **`aps.115.com/natsort/files.php`** | `webapi.115.com/files` 实测**被阿里云 WAF 拦截**（405 + "访问被阻断"，换 UA/加 Referer 均无效）；`aps` 返回正常业务响应 `{"state":false,"error":"请先登录"}` |
| 取播放直链 | `proapi.115.com/app/chrome/downurl` | 实测返回正常业务错误 `{"errno":99,"data":[]}`（只差 cookie） |
| 播放进度 | `webapi.115.com/files/history` | 待联调确认 |

> ★ **WAF 差异是本轮最重要的实测发现**：`webapi.115.com/files` 被拦，
> 但同域的 `/files/search`、`/category/get`、`/files/get_info` 都是 200。
> 说明是**具体路径级**的 WAF 规则，不是整站封禁——这也解释了为什么上游客户端
> 需要准备多个备用列表端点。

## ⚠️ 风险声明（使用前必读）

本决策**明确接受**以下风险，并已在 UI 中明示：

1. **非官方接口**：115 官方《开发须知》禁止调用非公开接口。本项目通过 webapi 访问，
   **可能违反 115 服务条款**。
2. **风控风险**：高频请求可能触发限流或限制账号。缓解措施：
   - 直链缓存 30 分钟，减少取址次数
   - 区分 403（限流 → 退避）与 401/410（过期 → 重取地址），**不混用**
   - 登录过期类错误立即停止重试（继续重试会被标记永久失效）
3. **随时可能失效**：115 可单方面变更接口。本模块的所有失败路径都有中文降级提示，
   **不会让应用崩溃或卡死**。
4. **凭据敏感**：cookie 四项等价于登录态。只存设备安全存储
   （`flutter_secure_storage` / Android Keystore），**绝不入库、不打日志**。

**放弃条件**（对应用户"如果不行的话放弃 115"）：
若文件列表或取直链**任一环节**在真机上无法稳定工作（连续 3 次不同时间测试均失败），
则按 ADR 0002 回退——保留代码但默认关闭入口，并把结论写回本 ADR。

## 与 Emby 的关系（MediaProvider 抽象）

`MediaProvider` 的边界类型已在同一轮重构中中立化（`Emby*` → `Media*`），
但**115 的播放模型与 Emby 根本不同**，抽象层还需扩展：

| | Emby | 115 |
|---|---|---|
| 层次 | 库 → 剧集 → 季 → 集 | 目录树（普通文件夹） |
| 播放源 | `PlaybackInfo` → `MediaSources[]` | `pick_code` → 直链（**单一源**） |
| 多版本 | `MediaSources[]`（不同文件） | ❌ 无（同一文件） |
| 播放头 | 仅 URL 带 token | **必须透传 UA + Cookie** |
| 进度 | `Sessions/Playing*` + `UserData` | `video/history`（5 秒去重） |

**本次不强行统一**：115 以独立页面/入口接入，`MediaProvider` 只新增真正共用的能力
（如 `resolvePlayback` 增加 headers 维度）。强行让 115 假装成 Emby 会产生
"季/集"这类无意义概念，反而更难维护。

## 后果

### 正面
- 扫码即用，**用户无需申请任何开发者资质**——这是与官方开放平台相比最大的可用性优势
- Go 侧实现可离线单测（零 cgo），协议契约有测试锁定
- UA 绑定这一最容易静默失败的环节，因"取地址与产出头同源"而在结构上被避免

### 负面 / 未完成
- **未真实联调**：本机可拿到二维码与状态，但**没有真实 115 账号**做端到端验证。
  协议实现有单测保证形状正确，但"能否真的列出文件、真的能播"**未经证实**
- 官方能力（清晰度列表、多音轨）在 webapi 路线上**拿不到**（那是开放平台的 `video/play`）
- 无下载/上传/分享能力（超出播放器范围）
